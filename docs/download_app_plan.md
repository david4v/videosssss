# 本地网页视频下载器实现思路

## 1. 产品目标与约束
- **目标**：为 macOS 打造一款本地运行的网页视频下载器，提供接近原生苹果应用的 UI，支持多站点视频解析、下载和管理。
- **平台**：macOS（Apple Silicon + Intel 双架构），后续可考虑 Windows/Linux 版本。
- **使用场景**：用户输入网页链接或自动嗅探网页中的媒体资源，实时显示下载进度，支持断点续传、批量任务和下载历史管理。
- **约束与挑战**：
  - 网站复杂多样、反爬虫频繁；
  - 视频编码格式繁多，需要转码整合；
  - macOS 沙盒、签名与打包要求；
  - 良好的用户体验与错误提示。

## 2. 整体架构
```
+-----------------------------------------------------------+
|                   桌面应用（前端 + 主进程）               |
|                                                           |
|  +-------------------+   IPC   +----------------------+   |
|  | 前端 UI (SwiftUI) | <-----> | 下载/解析服务 (Rust) |   |
|  +-------------------+         +----------------------+   |
|          |                               |                |
|          |                               |                |
|     系统 API (Network.framework, AVKit)  |                |
|                                          v                |
|                             扩展插件 (Python/Node)        |
+-----------------------------------------------------------+
```
- **前端层**：采用 SwiftUI 或 Catalyst 打造 macOS 原生界面，Electron 作为备选。
- **核心服务层**：使用 Rust/Go/Node 实现解析与下载引擎，通过 IPC 与前端通信；使用多进程隔离保证安全性。
- **扩展层**：支持插件或脚本（Python + yt-dlp、Node 的 puppeteer 等）处理特殊站点。

## 3. 功能模块划分
1. **任务管理器**
   - 新建/暂停/恢复/删除任务；批量导入链接；多队列管理。
2. **解析与嗅探器**
   - 静态解析：分析 HTML、抓取 m3u8/mpd/json API；
   - 动态解析：Headless 浏览器（Playwright/Puppeteer）执行 JS；
   - 嗅探模式：内置 mini 浏览器拦截媒体请求；
   - Cookie/Session 导入，支持登录态。
3. **下载引擎**
   - 支持 HTTP/HTTPS、RTMP、HLS、DASH；
   - 多线程分段下载、限速、断点续传；
   - 下载进度实时回传（速度、剩余时间、片段状态）。
4. **媒体处理**
   - FFmpeg 集成：合并音视频流、转封装、转码；
   - 元数据写入（标题、描述、封面）；
   - 编解码兼容性检测（H.264/H.265/AV1 等）。
5. **错误处理与重试**
   - 常见错误分类：网络错误、解析失败、反爬限制、解码失败；
   - 提示解决方案（代理设置、Cookie 更新、清理缓存）；
   - 自动重试策略（指数退避、备用解析器）。
6. **用户配置与持久化**
   - 设置下载路径、命名模板、最大并发数、代理；
   - SQLite/CoreData 保存任务、历史、Cookie、脚本；
   - 自动更新/插件市场。

## 4. UI/UX 设计要点
- **风格**：遵循 macOS 人机交互指南，使用半透明毛玻璃、圆角、系统字体；暗色模式适配。
- **布局**：
  - 左侧导航（下载队列、历史、设置、插件）；
  - 主视图显示任务列表，顶部展示进度汇总；
  - 右侧抽屉显示任务详情（媒体信息、分段状态、日志）。
- **交互**：
  - 拖拽链接至 Dock 图标或窗口即可新建任务；
  - 菜单栏快捷入口，支持快捷键；
  - 下载进度条与速度图；
  - 错误弹窗含解决建议与日志导出；
  - 初次启动提供引导教程。

## 5. 反爬与解析策略
- **网络层策略**：
  - 设置合适的 User-Agent、Referer、Headers；
  - 支持代理、请求节流、Cookie/Token 继承；
  - 模拟真实浏览器行为（TLS 指纹、指纹随机化）。
- **验证码/登录**：
  - 支持手动输入验证码或调用第三方识别；
  - 内置小型浏览器便于用户登录并注入 Cookie。
- **动态脚本对抗**：
  - 使用无头浏览器执行前端脚本获取真实接口；
  - 通过插件扩展使用站点专用解析脚本。
- **降级方案**：
  - 提供命令行工具（例如 yt-dlp）作为备份；
  - 对于 DRM 加密内容，明确提示无法下载或需外部方案。

## 6. FFmpeg 集成与异常诊断
- **交付策略**：
  - 优先随应用捆绑通用的 macOS (`arm64`/`x86_64`) FFmpeg 静态编译版本，首次启动时校验 SHA256；
  - 支持用户指定外部 FFmpeg 路径，并检测版本/编译配置（`ffmpeg -hide_banner -buildconf`）；
  - 在沙盒内运行时，通过辅助命令行工具或使用 FFmpegKit 等封装，确保签名与权限合规。
- **调用模型**：
  - 核心服务对 FFmpeg 进行进程级隔离，使用队列调度调用，传递转码/合并任务描述；
  - 统一封装命令模板，例如 `ffmpeg -protocol_whitelist file,http,https,tcp,tls,crypto -i <m3u8> ...`；
  - 通过 `-progress pipe:1`、`-loglevel error` 捕获实时进度与错误，映射到 UI 事件。
- **日志与诊断**：
  - 标准输出/错误统一保存，支持 UI 内查看与导出；
  - 引入解析器将 FFmpeg 日志转换成结构化信息（阶段、耗时、码率、警告）。
- **错误分类与恢复**：
  - 维护常见错误码字典（见下表），将 FFmpeg 退出码、`Error number`、WinSock/TLS 诊断转换为用户可读提示；
  - 结合网络模块重试策略（切换代理、TLS 选项、`reconnect_streamed` 参数）；
  - 针对 HLS/DASH，出现片段丢失时自动触发 `-reconnect 1 -reconnect_streamed 1 -reconnect_delay_max 10`；
  - 遇到防盗链时自动补充 `Referer`、`Origin`、Cookies 并回放；
  - 提供“在终端复现”按钮，便于用户直接执行诊断命令。
- **典型错误码对照**：

| 退出码/错误号 | 可能来源 | UI 文案与建议 |
|---------------|----------|----------------|
| `1` | FFmpeg 常规错误 | 检查命令参数是否正确，查看详细日志。 |
| `-541478725` (`AVERROR_EOF`) | 输入流提前结束 | 尝试重新下载缺失分段或降低并发。 |
| `-110` (`AVERROR(ETIMEDOUT)`) | 网络超时 | 建议切换网络/代理、增加超时时间。 |
| `4294967158`（等价 `-138`） | WinSock 报错或 TLS 握手失败导致 `tcp` 打开失败 | 记录 URL，提示“连接被远端拒绝/被中间件阻断”，自动降级为 `curl` 预取或启用 `schannel`/`openssl` 备用构建，必要时提示用户检查防火墙、证书。 |
| `-1330794744` (`AVERROR_HTTP_UNAUTHORIZED`) | 认证失败 | 引导用户更新 Cookie 或登录态。 |
| `-1094995529` (`Invalid data`) | 编码不兼容或流损坏 | 建议切换清晰度或启用转码修复。 |

- **针对 4294967158 / `Error number -138` 的专项处理**：
  - 在 UI 日志中展示原始 URL、目标主机、代理设置，提示其与网络策略有关；
  - 自动触发“协议探测”，用 `ffprobe -loglevel debug -i <url>` 复现，确认是 TLS/SNI、DNS 还是证书问题；
  - 若目标为 HLS/HTTPS，可尝试在命令中追加 `-tls_verify 0`、`-user_agent` 模拟、或使用 `--http_persistent 0` 切换连接模式（仅在用户确认后启用）；
  - 检测是否为地域封锁或速率限制，提供代理/镜像切换入口；
  - 将错误计入统计，便于后续收集站点兼容性数据。

## 7. 视频格式与编解码处理
- **分段流**：自动下载 TS/MP4 段并按顺序合并。
- **多音轨/字幕**：支持选择音轨、提取字幕（srt/vtt），允许多语言。
- **转码**：通过 FFmpeg 提供常见预设（MP4/H.264 + AAC、MKV、纯音频）；利用硬件加速（VideoToolbox）。
- **质量选择**：解析不同清晰度的 playlist，提供交互选择或自动匹配。
- **错误修复**：
  - 检测损坏片段，尝试重新下载；
  - 使用 FFmpeg 进行时间戳修复。

## 8. 打包与发布
- **工程结构**：
  - 核心下载服务作为独立库（Rust/Go），通过 FFI/IPC 嵌入；
  - SwiftUI 前端使用 Xcode 构建，集成核心库；
  - 使用 Swift Package Manager 管理依赖。
- **打包流程**：
  - 生成通用二进制（arm64 + x86_64）；
  - 使用 `pkgbuild` / `productbuild` 或 `notarization` 完成签名与公证；
  - 提供 DMG 安装包或 App Store 提交。
- **更新机制**：
  - Sparkle 框架实现自动更新；
  - 插件与解析脚本在线更新；
  - Crash/日志上传（用户许可）。

## 9. 技术选型建议
- **下载核心**：Rust (reqwest + tokio + ffmpeg bindings) 或 Go (colly + ffmpeg + rod)。
- **解析插件**：Python (yt-dlp)、Node.js (Playwright/Puppeteer)、Shell (aria2c)。
- **UI 实现**：SwiftUI + Combine；如需跨平台可考虑 Tauri/Electron + Vue/React。
- **数据存储**：SQLite（使用 GRDB/CoreData）管理任务与配置。
- **日志监控**：统一的日志模块，支持调试/发布级别切换。

## 10. 开发流程与里程碑
1. 原型设计：线框图、UI kit、交互流程。
2. 核心服务 MVP：实现基础解析 + 下载 + FFmpeg 合并。
3. UI 集成：SwiftUI 客户端管理任务、显示进度。
4. 扩展支持：加入插件系统、动态解析。
5. 错误处理与日志：完善提示、日志导出。
6. 打包发布：签名、自动更新、文档编写。
7. 长期维护：站点适配更新、社区插件。

## 11. 测试与质量保障
- 单元测试：解析器、下载器、队列调度。
- 集成测试：常见网站用例（YouTube、Bilibili、腾讯视频等）。
- UI 自动化测试：XCTest UI、Playwright。
- 性能测试：高并发任务、长时间下载、内存占用。
- 安全评估：沙盒权限、网络安全、证书管理。

## 12. 风险与应对
| 风险 | 描述 | 应对措施 |
|------|------|----------|
| 法律风险 | 某些网站禁止下载内容 | 在应用中加入免责声明与使用条款；仅供个人学习；允许用户导入 Cookie。 |
| 反爬升级 | 站点策略变化导致失效 | 插件化架构便于快速更新；提供远程脚本更新。 |
| DRM 加密 | 无法解密的受保护内容 | 明确提示不支持；提供参考解决方案链接。 |
| 性能瓶颈 | 大文件下载或转码耗时 | 支持硬件加速、任务调度优化、限速。 |
| 兼容性 | 不同 macOS 版本、芯片 | 自动测试矩阵；统一二进制。 |

## 13. 后续扩展
- 引入智能推荐（根据历史自动选择解析器）。
- 云端解析 API，与本地协同。
- 手机伴侣 App，同步下载列表。
- 局域网投屏、NAS 同步等增值功能。
